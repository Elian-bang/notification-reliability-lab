# 익명화 기준

이 저장소는 공개된다. 실제 운영 장애를 재현한 실험이므로,
**어느 회사 · 어느 업종 · 어느 날의 장애인지 특정되지 않도록** 이름을 바꿨다.

## 바꾼 것 — 이름뿐이다

| 원본 성격 | 이 저장소 |
|---|---|
| 도메인 테이블 (조직) | `tenant` |
| 도메인 테이블 (조직 소속 계정) | `member_account` |
| 도메인 테이블 (발송 대상 콘텐츠) | `content_item` |
| 콘텐츠 식별자 3건 | `A` · `B` · `C` |
| 장애 발생 벽시계 시각 | `T+0s` 기준 상대 시각 |

## 바꾸지 않은 것 — 수치다

측정값과 관측값은 **한 건도 손대지 않았다.**

- 락 보유 99초, 3건 한 트랜잭션, 발송 소요 72 / 65 / 32초
- 대상 8,540명, 접속 4건 중 3건 실패
- 재현 실험 결과 전부 (882 / 2,377 / 832 / 2,333 / 865 조회, 실패 3 / 0 / 3 / 0 / 3)
- `EXPLAIN` 의 `rows=3861` → `rows=1`

이름을 바꾼다고 **인과가 달라지지 않는다.**
`tenant` 든 무엇이든, 커밋 안 한 트랜잭션이 행을 붙잡고 있었다는 사실은 같다.

## 상대 시각 대응

| 상대 | 사건 |
|---|---|
| `T+0s` | 콘텐츠 A 발송 시작 (8,540명 · 72초) |
| `T+72s` | A 발송 끝 → 완료 표시 UPDATE — **여기서 A 행이 잠긴다** |
| `T+73s` | 콘텐츠 B 발송 시작 (65초) |
| `T+139s` | B 완료 → 콘텐츠 C 발송 시작 (32초) |
| `T+171s` | C 완료 → COMMIT — **99초 만에 A 락 해제** |

푸시를 받은 사용자는 `T+0s` 이후 20~90초 사이에 도착했다.
그 구간이 통째로 락 구간과 겹친다.
