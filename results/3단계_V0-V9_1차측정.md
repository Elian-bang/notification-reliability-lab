# 3단계 1차 측정 — V0 ~ V9

- 일자: 2026-09-02 · **1차. 반복 측정 전이므로 결론 확정 아님**
- 고정값: 테넌트 5 · 계정 1000 · 발송요청 4000 · 외부API지연 400us
  수신자 동시 12 / 간격 3ms · MySQL 8.0 (2 CPU / 2GB) · `innodb_lock_wait_timeout=5s`

## 결과

| # | 구성 | 수신자 데드락 | InnoDB 카운터 | 소요 |
|---|---|---|---|---|
| V0 | ① Tasklet (최초) | 33 | 33 | 13.0s |
| V1 | ② chunk 전환 | 43 | 43 | 12.7s |
| V2 | ③ 조회를 TX 밖으로 | **40** | 40 | 12.8s |
| **V3a** | ④a 벌크로 묶기 | **0** | 0 | 10.4s |
| **V3b** | ④b 알림 선생성·상태만 UPDATE | **0** | 0 | 13.1s |
| V3c | ④c 외부 API를 TX 밖으로 | 36 | 36 | 11.0s |
| **V6** | 운영 최종 조합 (③+④a+④c) | **0** | 0 | 10.8s |
| **V4** | 수신자 순서 통일 | **0** | 0 | 12.9s |
| V5 | READ COMMITTED | 43 | 43 | 13.2s |
| **V8** | **FK 제거** | **0** | 0 | 12.3s |
| **V9** | 수신자 TX 분리 | **0** | 0 | 12.3s |

배치 롤백은 **전 variant 0**. 죽는 쪽은 언제나 수신자다.

## 갈리는 선이 뚜렷하다

- **0 그룹**: V3a · V3b · V4 · V6 · V8 · V9
- **33~43 그룹**: V0 · V1 · V2 · V3c · V5

V0 는 앞선 실행들에서 45/46/45/48/33 으로 나왔다. **33~48 은 노이즈 범위**다.
그 안에 V1(43) · V2(40) · V3c(36) · V5(43) 이 전부 들어간다 — **서로 구분되지 않는다.**
반면 0 은 노이즈와 명백히 다르다.

## 확정 — FK 가 필요조건이다 (V8)

FK 를 떼면 데드락이 **0** 이다. 배치가 계정 행을 잠글 경로가 사라지므로 사이클이 성립하지 않는다.
2-b 단계에서 원문으로 본 `lock mode S ... waiting` 이 그 경로였다.

## 확정 — 락 보유 시간은 "왕복 횟수"가 지배한다

| | 트랜잭션 안 왕복 | 인위적 지연 | 결과 |
|---|---|---|---|
| V1 (건별) | INSERT+UPDATE+UPDATE × 500 = **1500회** | 500회 × 400us | 43 |
| V3c (건별, API 밖) | **1500회** | **0회** | 36 |
| V3a (벌크) | batchUpdate **3회** | 1회 × 400us | **0** |

**지연을 전부 빼도(V3c) 36 건이 난다.** 왕복 1500회 자체가 락을 오래 쥔다.
반대로 왕복을 3회로 줄이면(V3a) 지연이 남아 있어도 0 이다.

→ **락 보유 시간 = 왕복 횟수 × 왕복 시간.** 지배항은 왕복 횟수였다.

## 이력서와 배치되는 결과

현재 이력서 서술:

> **조회를 트랜잭션 밖으로 분리**해 락을 쥔 채 대기하는 구간 자체를 제거한 것이 **근본 조치**였고,
> 상태 갱신을 **BATCH UPDATE** 로 전환해 락 점유 시간을 추가로 줄임

1차 측정은 **반대**를 가리킨다.

| 이력서 표현 | 대응 variant | 결과 |
|---|---|---|
| "근본 조치" — 조회를 TX 밖으로 | V2 | **40** (baseline 과 구분 안 됨) |
| "추가로 줄임" — BATCH UPDATE | V3a | **0** |

**조회를 빼도 쓰기 왕복 1500회는 그대로 남는다.** 그래서 효과가 안 나온다.
근본을 바꾼 건 벌크화 쪽이다.

> ⚠️ **아직 이력서를 고치지 않는다.** 1회 측정이고, V2 는 "효과가 없다"가 아니라
> **"효과를 확인할 수 없다"** 가 정확하다. 반복 측정 후 판단한다.

## 이번 측정의 한계 (다음에 고칠 것)

1. **V5 는 반쪽이다.** 격리수준이 수신자에만 적용되고 배치 chunk 트랜잭션에는 안 걸린다.
   트랜잭션 매니저 충돌을 고치면서 빠졌다.
2. **지표 수집에 레이스가 있다.** 배치가 지표를 읽는 시점(작업 종료 +1.2s)과
   수신자의 flush 주기(300ms)가 어긋나면, 종료 직후 실패가 다음 집계로 넘어가거나
   이전 run 에 붙는다. 실제로 V3b 가 콘솔 0 · DB 2 로 갈렸다.
   **InnoDB 카운터가 교차 검증 역할을 했다** (0 확인).
3. **V3a 는 변수 두 개가 같이 움직인다.** 벌크화하면 왕복도 줄고 인위적 지연 횟수도
   500 → 1 로 준다. 왕복만 줄인 조건을 따로 둬야 완전히 분리된다.
   다만 V3c 가 지연을 전부 뺐는데도 36 이라, **왕복이 지배항**이라는 결론 자체는 흔들리지 않는다.
